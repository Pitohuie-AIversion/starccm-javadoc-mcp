## 2024-11-06 - Fixing WPF Screen Reader Labels
**Learning:** In WPF (like this repo's `MainWindow.xaml`), standard HTML `id`/`for` attributes don't exist. Inputs left unlabeled cause screen readers to read them out of context. The `ToolTip` property does not solve labeling for inputs like `TextBox`, and relying purely on visual proximity (like a `TextBlock` next to a `TextBox`) fails for screen readers.
**Action:** Use `AutomationProperties.LabeledBy="{Binding ElementName=YourHeadingName}"` on input elements to programmatically associate them with adjacent headings or text blocks. For tooltips on icon-like elements or vague buttons (e.g. "Browse..."), setting `ToolTip` provides the accessible name. Always ensure any new strings are added to localization dictionaries (e.g. `strings.json`) if the app supports multiple languages.
